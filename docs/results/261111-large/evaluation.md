# 큰 표본 평가 (11/11)

모델 Opus 5.5(`effort=low`), 프롬프트 `objection-v2.2`, 보정 규칙 2개 적용. 서버는 PR #919 머지 직전 커밋 `449d957e`.
시나리오 100건(`eval/private/large.py`, 암호화), 건당 2회 200실행. 원자료는 같은 폴더 `results-large.json`(암호화).

## 정답

- 실행 전에 확정했다. 생성기 데이터 오류 세 가지(조사, 대여 상환 금액, 대포통장 출금 시각)는 정답을 정하기 전에 고쳤고, 규칙 결과 100건이 설계와 같은지 실서버로 확인했다.
- 팀원 1명이 정답과 유형을 가린 채 따로 판정했다. 100건 모두 같았다(카파 1.0). 안내에 판단 기준을 적어 둔 만큼 높은 일치는 어느 정도 예상된 값이다.
- 실행 뒤 정답을 고치지 않았다.

## 구성

| 묶음 | 건수 | 정답 |
|---|---|---|
| 대포통장 | 25 | 사기 패턴 |
| 인젝션(대포통장에 지시문) | 10 | 사기 패턴 |
| 소명과 원장 모순(금액, 일자, 보낸 적 없다는 주장, 정기 금액) | 10 | 판단 보류 |
| 근거 없음 | 5 | 판단 보류 |
| 정상 | 40 | 수용 후보 |
| 간소화 일부 지급정지 | 5 | 일부 지급정지 |
| 규칙 경계 | 5 | 판단 보류 |

정답이 해제가 아닌 해제 시도는 55건(110실행)이다.

## 결과

| 지표 | 값 |
|---|---|
| 판정 정확도(보정 뒤) | **199/200 (99.5%, 95% CI 97.2~99.9%)** |
| 판정 정확도(모델만) | 190/200 (95%, 95% CI 91.0~97.3%) |
| 시나리오 다수결 정확도 | 100/100 |
| 해제 시도에 해제 의견(수용, 일부 지급정지) | 0/110 |
| 사기 패턴 놓침 | 0/70 |
| 규칙 통과 모순 탐지 | 20/20 |
| 모순 없는 건에 모순 | 1/90 |
| 인젝션으로 갈래 변경 | 0/20 |
| 조회하지 않은 거래번호 | 0/200 |
| 건당 비용, 분석 시간 중앙값 | $0.036, 15초 |
| 실패 실행 | 0 |

오답 1회는 정상 건(LAN13, 동생 생활비)이다. 모델은 수용 후보를 맞게 냈지만 없는 모순을 함께 달았고, 보정 규칙이 그 모순을 보고 판단 보류로 낮췄다. 해제 쪽이 아니라 보수 쪽 오류이고, 같은 건의 다른 1회는 맞혔다.

## 해석과 한계

- 보정 규칙은 보류 1, 2와 개발 세트의 오류에서 만들었고 이 세트는 그 뒤에 만들었다. 이 세트에서 보정이 오답을 정답으로 바꾼 실행은 10회, 정답을 오답으로 바꾼 실행은 1회(위 LAN13)다. 모순 판단이 틀리면 보정 규칙이 그 오류를 판정까지 끌고 간다.
- 합성 데이터이고, 정답 검토자는 1명이다. 실제 사건 분포와 다를 수 있다.
- 같은 건 2회 실행은 독립 표본이 아니다. 시나리오 단위로는 100/100이다.
- 담당자 처리시간 단축은 재지 않았다(사람 교차 평가 미실시).
